## `kurama s3`

`kurama s3 <S3>` lists what an S3 bucket holds with the role of an `[s3.*]`
connection: it assumes the role once per run. `--head`, `--preview` and
`--search-content` read one object's metadata or a bounded part of its
contents. `kurama agent --kind s3 --json` lists the operations, the flag that
selects each and the bounds a run takes when it names none, without reading
config.toml; `kurama status --kind s3 --json` lists the configured
connections without assuming a role or reaching S3.

```bash
kurama s3 assets --list --json
kurama s3 assets --buckets --json
kurama s3 assets s3://example-assets/reports/ --list --recursive --max-objects 500 --json
kurama s3 assets s3://example-assets/reports/ --search invoice --json
kurama s3 assets s3://example-assets/reports/ --search invoice --dry-run --json
kurama s3 assets s3://example-assets/reports/result.json --head --json
kurama s3 assets s3://example-assets/reports/result.json --preview --bytes 65536 --json
kurama s3 assets s3://example-assets/reports/result.json --preview --offset-bytes 65536 --if-match '<etag>' --json
kurama s3 assets s3://example-assets/logs/ --search-content request-id-123 --max-objects 100 --json
```

```toml
[s3.assets]
aws_profile = "dev"            # required: the role that reads the bucket
region = "ap-northeast-1"      # where the first request is signed
bucket = "example-assets"      # start of --list / --search without TARGET
prefix = "reports/"            # needs bucket; a start, not a permission boundary
page_size = 200                # keys per ListObjectsV2 page, 1-1000
request_timeout_secs = 30      # per S3 request
```

One operation is required and they are exclusive: `--buckets` (every bucket
`ListBuckets` answers), `--list` (one level: `prefixes` and `objects`, or
every key under the prefix with `--recursive`) or `--search TEXT` (the keys
under the prefix that contain TEXT, case-sensitive and never a pattern).
Without one the run is `S3_INVALID`, exit 2. `TARGET` is `s3://bucket` or
`s3://bucket/prefix`, read as written: `%`, `+`, spaces, `..` and repeated
`/` are part of the key. Without it the `[s3.*]` bucket and prefix are used.
A denied `ListBuckets` does not stop `--list` or `--search` of a bucket you
name.

The region is `--region`, then the `[s3.*]` `region`, then the AWS
profile's; none is exit 2. It says where the first request is signed: a
bucket in another region answers with its own, which is followed, and the
result's `region` is where the bucket was read.

Each run examines at most `--max-objects` keys and prefixes (default: the page
size for `--list`, 1000 for `--search`) and reports `scanned_objects`,
`complete` and `stop_reason`. `complete: false` with `stop_reason:
"max_objects"` means the run stopped, not that nothing is left: pass its
`cursor` to `--cursor` with the same TARGET, operation, `--recursive` and
`--search` to go on, without skipping or repeating a key. `complete: true`
with no objects means there are none. Without `--json` the result is a
tab-separated table on stdout and the cursor goes to stderr. `--dry-run`
prints the target, operation and bounds without calling STS, S3 or
1Password.

### Reading an object

`--head` sends one `HeadObject` for the key TARGET names and reports `object`:
`size`, `content_type`, `content_encoding`, `last_modified`, `etag`,
`storage_class` (`STANDARD` when S3 names none), `restore` and
`archive_status`. `--head` and `--preview` need a key, not a prefix.

`--preview` sends the same HEAD, then one `GetObject` for a range, conditional
on the ETag HEAD answered (or on `--if-match ETAG`, which fails as soon as the
object no longer has it). It shows at most `--bytes` (default 65536, at most
1048576) from `--offset-bytes` (default 0). `preview.kind` is `text`, `binary`
(only `hex`, the first 64 bytes) or `empty` (no GET). A range that cuts a
UTF-8 character is trimmed to whole characters (`utf8_head_skipped`,
`utf8_tail_cut`) and `next_offset` is where the next run starts; it is `null`
at the end, where `complete` is `true`. `format` (`json`, `jsonl`, `yaml`,
`csv`, `text`) comes from the key and the type; `well_formed` says whether
JSON shown is one whole document (a cut range is shown as text, not refused).
A gzip object (`.gz`, `Content-Encoding` or type) is decoded from its start:
at most 1 MiB is transferred and `--bytes` decoded, `next_offset` is `null`,
`complete` is `true` only when the whole stream decoded, and `--offset-bytes`
is refused (`S3_INVALID`). An archived object (Glacier, Deep Archive, an
archive tier) is reported under `skipped` and not read. Parquet is binary
here: read its schema and rows with `kurama data`.

`--head` and `--preview` of a key `kurama data` reads (`.csv`, `.jsonl`,
`.ndjson`, gzip of those, `.parquet`) carry `next_actions`: one entry with
`kind: "data"`, `operation: "describe"`, `args` (`from`, the exact
`s3://bucket/key`, and `s3_source`, this `[s3.*]`) ready for
`kurama data --request -`, `provenance` (`etag`, `size`, `last_modified` as
this run saw them) and a `message` with the command line. Nothing runs it,
and `kurama data` reads the object again: it does not assume the version is
the one seen here. Any other key has `next_actions: []`.

`--search-content TEXT` lists the objects under the prefix like `--search`
(`--max-objects`, default 100, and `--cursor` for the listing), then reads
each in turn and reports every line that contains TEXT (case-sensitive,
never a pattern) under `matches`: `bucket`, `key`, `line`, `byte_offset`, an
`excerpt` of at most 256 characters and `fetched_at`. gzip is decoded. The
bounds are kurama's: 8 MiB transferred and 8 MiB decoded per object, 50 MiB
each per run, 1000 matches. `searched` lists each object read with whether it
was read `full`; `skipped` names each object not read and why (`archived`,
`too_large`, `binary`, `invalid_gzip`, `changed` -- its ETag is no longer the
listed one -- or `not_reached` after a stop). `stop_reason` is `max_objects`,
`max_bytes` or `max_matches`. `complete: true` with no matches means every
object under the prefix was read in full and none contains TEXT; anything
skipped or stopped makes it `false`. `bytes_read` and `bytes_decoded` say
what was transferred and decoded. Without `--json` the matches are a
`key`/`line`/`excerpt` table and what was not searched goes to stderr.
Contents are never written to disk or logged; control characters are escaped
in text output.

On a terminal, `kurama s3 <S3>` with no operation (and no `--json` or
`--dry-run`) opens the S3 explorer instead, from TARGET, the `[s3.*]` bucket
and prefix, or the bucket list; without a terminal it is `S3_INVALID`, exit 2,
as before. An agent uses the flags above.

Failures: a refusal by S3 (`AccessDenied`, `NoSuchBucket`) is `S3_REJECTED`,
exit 4, and so is a read refused (`AccessDenied`, `NoSuchKey`) or an object
that changed under `--if-match`; no answer (network, timeout) is `S3_FAILED`, exit 1; an MFA or login
that needs a person keeps its own code and exit 3. A failure is never an empty
list. With `--json` the error is one JSON document on stderr.

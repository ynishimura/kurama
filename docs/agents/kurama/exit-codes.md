## Exit codes

| Code | Meaning | Next step |
| --- | --- | --- |
| 0 | success | continue |
| 1 | tool error: network, timeout, a jq error, a description that cannot be fetched or read, config.toml that cannot be saved (`CONFIG_WRITE_FAILED`) | read the `error[CODE]` line |
| 2 | usage: unknown profile or API, invalid config, a verb the kind does not support (`token dev`, `console github`), `kurama` without a command and without a terminal, `exec` could not start the command, a missing or malformed `TARGET`, a SigV4 service or region that cannot be told, an unknown operation, a missing or invalid operation parameter, no `openapi` for `--ops` / `--describe` / `--schema` / `--skill`, an unusable description, a preset id the catalog lacks (`PRESET_NOT_FOUND`), sections `config add` refuses (`CONFIG_INVALID`: a name the file already has, a literal secret), what `preset show` / `preset add` refuse in their arguments (`ARGUMENT_INVALID`: a missing or unknown input, a `--set` value whose section is refused, naming the key, a literal secret, an API name the file already has, an auth that cannot be reused; an auth named like an AWS profile stays `CONFIG_INVALID`), edits `config set` / `unset` / `remove` refuse (`CONFIG_INVALID`: a key or section the file lacks, one given twice or with the section holding it, an `[auth.*]` an API still uses). A bad argument clap rejects prints clap's usage text and no `error[CODE]` line, unless the subcommand reports its own usage failures (`usage_error` in `kurama agent --json`): `data` and `db` always, `api`, `status`, `env`, `token`, `config` and `preset` only under `--json` or `--jq`, with `DATA_INVALID`, `DB_INVALID`, `API_ARGUMENT_INVALID` or `ARGUMENT_INVALID`, as one JSON error document under `--json` or `--jq` | fix the arguments; `kurama status` lists the names, `kurama api <API> --ops` the operations, `--describe <OP>` the parameters |
| 3 | a person must act | pass the `hint:` line to the person (`kurama login <source>` in a terminal, `op signin`, an unlocked keychain) |
| 4 | the remote side rejected the request: AWS, an authorization server, an HTTP status outside 2xx | check the role, the client, or the request |
